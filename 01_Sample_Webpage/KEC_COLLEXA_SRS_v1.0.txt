1. INTRODUCTION

1.1 Purpose

This Software Requirements Specification (SRS) defines the functional and non-functional requirements for a web-based smart college portal for Kathmandu Engineering College (KEC). The system will combine a modern college website, student and administration portals, admission/seat booking services, appointment management, result checking, and an AI-powered conversational agent named COLLEXA.

COLLEXA will act as an intelligent natural-language interface through which users can obtain general KEC information and, where authorized, perform supported college services such as checking results, booking appointments, checking seat availability, reserving admission seats, and confirming registration.

This document is intended for project developers, designers, testers, administrators, college stakeholders, and future maintainers.


1.2 Scope

The system will provide the following major capabilities:

- Public KEC information website
- COLLEXA AI conversational agent
- RAG-based KEC information retrieval
- Student registration and login
- Student dashboard
- Student result lookup using authenticated student identity/IOE Roll Number
- Appointment booking with faculty/administration
- Engineering program seat availability
- Admission seat reservation
- Registration confirmation
- QR-based registration verification
- Administrator login and dashboard
- Student, result, seat, booking, appointment, program, and notice management
- KEC document and knowledge-base management
- Role-based access control
- Audit and security controls
- Notice and Recent Updates 
- News Sections 
- Gallery consisting image/videos of the KEC college in the website

Initial academic programs covered by the admission booking module:

- Computer Engineering
- Communication, Electronics and IT Engineering
- Electrical Engineering
- Architecture
- Civil Engineering

The system should be designed so additional programs can be added later.

2. OVERALL DESCRIPTION

2.1 Product Functions

The system shall:

1. Present official KEC information through a public website.
2. Allow users to interact with COLLEXA.
3. Answer general KEC-related questions using an approved knowledge base.
4. Authenticate students and administrators.
5. Provide authenticated students with personalized services.
6. Allow students to view their academic results.
7. Allow students to request and manage appointments.
8. Display live seat availability for supported engineering programs.
9. Allow eligible users to reserve available seats.
10. Allow users to explicitly confirm registration.
11. Generate a QR registration credential after successful confirmation.
12. Allow authorized administrators to manage system information.
13. Provide administrators with booking, seat, student, result, and appointment information.
14. Allow authorized personnel to update the COLLEXA knowledge base.
15. Maintain logs/audit records for important administrative and transactional actions.

Permissions:

- Browse public KEC information
- View programs
- View admission information
- View notices
- View departments
- View contact information
- Ask general questions to COLLEXA
- View public seat availability, if enabled
- Access login/register pages


2.2.2 Student

An authenticated KEC student.

Permissions:

- Access student dashboard
- View own profile
- View own results
- View permitted academic information
- Book appointments
- View/cancel own appointments
- Check program seat availability
- Make permitted seat reservations
- Confirm registration
- Access generated QR registration credential
- Interact with authenticated COLLEXA services


2.2.3 Administrator

An authenticated authorized administrator.

Permissions may include:

- Access admin dashboard
- Manage students
- Manage programs
- Manage seats
- Manage results
- Manage appointments
- Manage bookings
- Manage registrations
- Publish/manage notices
- Upload/manage knowledge-base documents
- View system statistics
- Review audit logs
- Manage selected system settings


2.2.4 Super Administrator

Optional higher-privilege role.

Additional permissions:

- Create/remove administrators
- Assign roles
- Configure system-wide settings
- Manage sensitive security settings
- Access all administrative functions

Student

1. Student logs in.

3. Student requests a result.

9. BOOKING BUSINESS RULES

BR-001:
A booking shall only be created when a seat is available.

BR-002:
A user shall not create duplicate active bookings for the same restricted program unless explicitly permitted.

BR-003:
A temporary booking shall have an expiration time.

BR-004:
Expired bookings shall release their reserved seats.

BR-005:
A booking shall not become a confirmed registration without explicit confirmation.

BR-006:
A QR registration credential shall only be generated for a valid confirmed registration.

BR-007:
The system shall use transactional database operations when modifying seat availability.

BR-008:
The backend shall be the final authority for booking validity; COLLEXA shall not determine validity on its own.


10. SECURITY AND AI SAFETY RULES

SR-001:
COLLEXA shall not directly access unrestricted database tables.

SR-002:
Every tool call shall be validated by the backend.

SR-003:
Authenticated operations shall use the authenticated user's identity rather than trusting identity values supplied solely by the LLM.

SR-004:
COLLEXA shall not disclose private student data to unauthorized users.

SR-005:
The system shall require confirmation for irreversible or consequential operations.

SR-006:
Prompt injection within uploaded documents shall not be allowed to override system permissions.

SR-007:
Retrieved documents shall be treated as data, not as privileged system instructions.

SR-008:
Administrative tools shall require administrator authorization independent of COLLEXA's decision.

SR-009:
Sensitive values shall not be included in logs unnecessarily.

SR-010:
Secrets and API keys shall be stored outside source code.

17. ACCEPTANCE CRITERIA

The system shall be considered functionally acceptable when:

1. A public user can browse KEC information.
2. A public user can ask COLLEXA general KEC questions.
3. COLLEXA can retrieve information from the approved KEC knowledge base.
4. A student can securely log in.
5. An authenticated student can view their own results.
6. A student can book an available appointment.
7. A user can view current program seat availability.
8. An eligible user can reserve an available seat.
9. A reservation can expire according to configured rules.
10. A user must explicitly confirm before registration.
11. A confirmed registration generates a valid QR credential.
12. QR verification correctly identifies valid/invalid registrations.
13. Administrators can manage students, results, programs, seats, bookings, appointments, and notices according to their permissions.
14. Administrators can manage the COLLEXA knowledge base.
15. Unauthorized users cannot access protected student/admin information.
16. Concurrent seat booking does not cause inconsistent seat counts.
17. Important transactional and administrative actions are auditable.

19. CONCLUSION

The proposed KEC Smart Web Portal will provide a unified digital platform for public information, student services, admissions, appointments, administration, and AI-assisted interaction.

COLLEXA will serve as the intelligent conversational layer of the platform while controlled backend APIs remain responsible for authentication, authorization, database access, transactional operations, and business rules.

The separation between the AI agent and core backend services is a key architectural requirement. It allows COLLEXA to provide natural-language interaction without giving the language model unrestricted authority over sensitive student or administrative data.

The system is intended to be modular and extensible so that additional KEC services can be integrated into COLLEXA in the future.
